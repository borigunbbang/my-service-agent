== 요청 ==
다음 세 문장을 저장해 줘: "환불은 구매 후 7일 이내에 가능하다." "배송은 영업일 기준 2일이 걸린다." "회원 등급은 매월 1일에 갱신된다." 그리고 "환불 기한이 어떻게 돼?"와 비슷한 문장을 찾아 줘.

== [1] 모델이 고른 도구와 인자 (순서대로) ==
(도구 아님) ToolSearch: qdrant-store, qdrant-find 도구 정의 불러오기
(도구 아님) Bash: ls -la; cat .mcp.json  ← 설정 확인용, 요청에 없던 행동
qdrant-store {"collection_name": "policies", "information": "환불은 구매 후 7일 이내에 가능하다."}
qdrant-store {"collection_name": "policies", "information": "배송은 영업일 기준 2일이 걸린다."}
qdrant-store {"collection_name": "policies", "information": "회원 등급은 매월 1일에 갱신된다."}
qdrant-find  {"collection_name": "policies", "query": "환불 기한이 어떻게 돼?"}

== [3] 최종 답 (요약) ==
세 문장을 policies 컬렉션에 저장하고 검색함. 1위 "환불은 구매 후 7일 이내에 가능하다.", 2위 회원 등급 문장, 3위 배송 문장.
참고로 밝힌 점: 유사도 점수가 없어 순서만 알 수 있음 / 영어용 임베딩 모델이라 한국어 비교가 부정확할 수 있음(2·3위 순서는 의미상 근거 약함) / :memory: 저장이라 서버 재시작 시 사라짐.

== 관찰 ==
1. 도구 주입: .mcp.json만 저장했는데 qdrant-store, qdrant-find 두 도구가 Claude Code에 들어왔다.
2. 도구 선택: "저장해 줘"에는 store(3번, 문장마다 1번), "찾아 줘"에는 find(1번)를 골랐다. 두 도구의 쓰는 때가 겹치지 않아 헷갈리지 않았다.
3. 인자: 문장과 질문을 바꾸지 않고 원문 그대로 넣었다.
4. 결과 사용: 글자가 같지 않아도 뜻이 가장 비슷한 환불 문장을 1위로 찾았고, 그 결과를 근거로 답했다.
5. 한계: 한국어 문장에 영어용 임베딩 모델을 써서 2·3위 순서는 믿기 어렵다. 저장이 메모리라 세션이 끝나면 사라진다.
