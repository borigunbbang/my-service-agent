참고할 점이 두 가지 있어.
- **점수가 안 나와:** 이 검색 도구는 유사도 점수를 주지 않고 순서만 알려 줘. 그래서 1위가 2·3위보다 얼마나 앞섰는지는 알 수 없어.
- **임베딩 모델이 영어용이야:** `.mcp.json`에 설정된 모델이 영어용인 `BAAI/bge-small-en-v1.5`야. 문장이 셋뿐인 이번 테스트는 잘 됐지만, 한국어 문서가 많아지면 정확도가 떨어질 수 있어. 그럴 땐 `intfloat/multilingual-e5-small` 같은 다국어 모델로 바꾸는 걸 권해.
- **저장 위치가 메모리야:** `QDRANT_URL`이 `:memory:`라서, MCP 서버가 다시 시작되면 저장한 문장이 사라져.

== 관찰 ==
1. 도구 주입: MCP 서버가 연결되자 qdrant-store, qdrant-find 두 도구가 모델의 도구 목록에 들어왔다.
2. 도구 선택: 저장 요청에는 qdrant-store를 3번(문장마다 1번), 검색 요청에는 qdrant-find를 1번 골랐다. 두 도구의 "쓰는 때"가 겹치지 않아 선택이 헷갈리지 않았다.
3. 인자: store는 {collection_name, information}, find는 {collection_name, query}. 문장과 질문을 바꾸지 않고 원문 그대로 넣었다.
4. 결과 사용: 검색 결과 1위(환불 문장)를 근거로 답했다. 유사도 점수는 도구가 돌려주지 않아 답에서도 "순서만 알 수 있다"고 밝혔다.
5. 기타: 도구를 쓰기 전에 Bash로 .mcp.json을 한 번 읽었다(요청에 없던 행동).
6. 인메모리 저장이라 세션(서버 프로세스)이 끝나면 저장한 세 문장은 사라진다.
