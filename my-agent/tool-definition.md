# 도구 정의서: get_inventory

> 실습 1 산출물. 고객이 "부산 창고의 A-17 재고"를 물었을 때 모델이 창고와 상품을 추측하지 않도록 계약을 고정한다.

## 1. 도구 정의서 (6항목)

| 항목 | 내용 |
|---|---|
| 이름 | `get_inventory` |
| 하는 일 한 문장 | 승인된 창고에 있는 특정 SKU의 가용 수량을 읽기 전용으로 조회하며, 수량을 수정하지 않는다. |
| 쓰는 때 | 고객이 승인된 창고(SEOUL-01, BUSAN-02)에 있는 특정 SKU의 재고 수량을 물을 때 |
| 쓰지 않는 때 | ① 수량을 바꾸라는 요청(입고, 출고, 수량 조정)에는 쓰지 않고, 이 도구로는 할 수 없다고 안내한다. ② 창고나 SKU를 알 수 없으면 호출하지 않고 고객에게 먼저 묻는다(추측 금지). ③ 재고 수량이 아닌 질문(창고 위치, 배송 일정 등)에는 쓰지 않는다. |
| 인자 스키마 | `sku`: 문자열, 3~32자, 필수. 고객이 말하지 않았으면 비슷한 상품으로 대신하지 않는다.<br>`warehouse_id`: 문자열, 필수. 허용값은 `SEOUL-01`, `BUSAN-02` 두 개뿐이다. 그 외의 코드는 만들어 넣지 않는다. |
| 반환 형식 | 성공하면 `sku`, `warehouse_id`, `available_quantity`, `checked_at` 네 필드만 돌려준다. 원가 같은 내부 데이터는 반환하지 않으며, 최종 답은 `available_quantity`와 `checked_at`만 근거로 쓴다. 실패하면 `error` 코드 하나만 돌려준다. |
| 실패 정의와 뒤 행동 | 아래 표 참고 |

### 실패 정의와 뒤 행동

| 오류 코드 | 언제 생기나 | 뒤 행동 (재시도 / 질문 / 중단 중 하나) |
|---|---|---|
| `WAREHOUSE_NOT_ALLOWED` | 허용 목록에 없는 창고 코드로 호출했을 때 (예: "부산 3번 창고") | **질문**: 재호출하지 않고, 허용된 창고(SEOUL-01, BUSAN-02) 중 어디인지 고객에게 묻는다. |
| `INVALID_SKU` | 존재하지 않거나 형식이 맞지 않는 SKU로 호출했을 때 | **질문**: 비슷한 상품을 추측해 다시 조회하지 않고, 정확한 SKU를 확인해 달라고 묻는다. |
| `TIMEOUT` | 재고 서버가 제시간에 응답하지 않을 때 | **재시도 1회 → 중단**: 같은 인자로 한 번만 다시 호출한다. 또 실패하면 수량을 추정하지 말고 "지금은 조회할 수 없다"고 알린 뒤 멈춘다. |

## 2. 실행 전 채점 기준

| 기준 | 통과의 정의 (예/아니오로 판정) | 확인 위치 |
|---|---|---|
| 스키마 준수 | 호출이 3~32자의 `sku`와 허용된 `warehouse_id`(SEOUL-01, BUSAN-02)만 사용했다. | 도구 호출 인자 |
| 호출 성공 | 유효한 입력에서 성공 응답이 오거나, 표에 정의된 오류 코드가 돌아왔다. | 도구 응답 |
| 결과 사용 가능성 | 최종 답이 `available_quantity`와 `checked_at`만 근거로 삼았다(원가 등 다른 값 인용 없음). | 최종 답변 |
| 실패 처리 | 오류가 난 뒤 수량을 추정하지 않고, 위 표에 정해진 행동(질문, 재시도 1회, 중단)을 택했다. | 호출·최종 답변 |

## 3. 실패 사례 → 비어 있던 칸 → 보완 문장

| 실패 사례 | 비어 있던 칸 | 보완 문장 |
|---|---|---|
| 존재하지 않는 창고 코드를 임의로 넣어 같은 오류를 반복 호출했다 | 인자 스키마, 실패 뒤 행동 | `warehouse_id`는 SEOUL-01, BUSAN-02만 허용한다. 허용되지 않은 창고면 재호출하지 않고 허용 코드를 묻는다. |
| SKU를 모른 채 가장 비슷한 상품을 골라 조회했다 | 인자 스키마, 실패 뒤 행동 | `sku`는 필수이다. 없거나 불확실하면 비슷한 상품으로 대신하지 않고 상품 식별자를 묻는다. |
| 응답의 내부 원가를 최종 답에 인용했다 | 반환 형식 | 반환은 `sku`, `warehouse_id`, `available_quantity`, `checked_at`로 제한하고, 답의 근거는 가용 수량과 확인 시각만 쓴다. |

## 4. 정리

세 실패는 모두 모델이 잘못 행동한 것처럼 보이지만, 되짚어 보면 정의서의 빈 칸(인자 스키마, 반환 형식, 실패 뒤 행동) 때문이었다. 도구 설명은 모델이 읽는 프롬프트이므로, 허용값과 반환 필드, 실패 뒤 행동을 구체적으로 적어 두어야 모델이 빈자리를 추측으로 메우지 않는다.
